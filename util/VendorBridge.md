# VendorBridge: tool guide for TrophySyncVendorBridge answers questions about trophy vendors' products, read from each vendor's **public website**: product details, photos, options, variants, quantity pricing and art templates. It never uses the vendors' PromoStandards services, so it is an independent second source next to TrophySync's PromoStandards feed. How TrophySync combines the two is up to TrophySync.This guide describes VendorBridge as a set of tools, in the MCP style: a name, when to use it, an input schema, the output, and the errors. Each tool is one HTTP GET, so it maps one-to-one onto an MCP tool or a plain function.---## Connection| | ||---|---|| Base URL | `https://vendorbridge.yoordy.com` || Auth | `Authorization: Bearer <key>` on every call except `/health` || Your key | TrophySync's own key (client name `trophysync`). Keep it in TrophySync's server-side secrets. || Format | JSON in and out; `template.pdf` returns `application/pdf` || Scope | `vendors:read` (every tool below) |Rules for the key:- **Never send it from a browser, a storefront page or a theme.** A key in page JavaScript is a published key. Call VendorBridge from TrophySync's server only.- If it leaks, ask for it to be revoked and replaced (`vb-keys revoke trophysync` on the server). Revocation takes effect immediately.Health check, no key needed: `GET /health` → `{"ok": true}`.---## Concepts every tool shares**`vendor`**: the vendor's id in the path. Today: `visions`, `pacesetter`. Call `list_vendors` for the current set, and `get_vendor` to see which tools each one answers (`capabilities`).**`part`**: what you ask about. It can be:- the vendor's SKU (`FS-1370-S`, `CD41A`);- one of our own part codes, which VendorBridge matches loosely (`DCCD41A`, `CD41ABL`, `FS-998V`);- the vendor's own product key, the `vendor_product` from a search result (`verge` for Visions, the page id `4784` for PaceSetter).URL-encode it. Part codes contain no `/` today.**`resolution`**: in every answer about a part, it says how the part was found. **Read `matched_by` before trusting the match:**| `matched_by` | meaning | trust ||---|---|---|| `exact` | the vendor lists this exact code | safe || `no-punct` | the same code once punctuation is ignored (`fs1370s` → `FS-1370-S`) | safe || `handle` | you passed the vendor's own product key | safe || `recoded` | a known transformation: a Digi-Color `DC` prefix, a colour suffix (`CD41ABL` → `CD41A`), or a suffix the vendor dropped (`FS-998V` → `FS-998`) | usually right; check `matched_sku` || `prefix` / `prefix-no-punct` | the longest vendor code your part starts with (`GI582MS` → `GI582M`) | **review**: it may be a neighbouring model |`resolution.vendor_product` is the vendor's product key, and `resolution.matched_sku` the vendor SKU the part resolved to (null when you asked by product key).**`source`**:- `source.url` is the vendor page the answer describes.- `source.catalog_date` is when that vendor's catalog was last crawled (ISO 8601). Catalogs refresh weekly, on Sunday around 04:30 UTC.- `catalog_date` is null when the answer was read live: a product found only through the vendor's own search.**Empty list vs. not supported:** an empty list means "this product has none". A tool the vendor can't answer at all is a **501**, never an empty list.**Prices are USD, per piece.** `price` is the vendor's price at its lowest quantity break. It is the vendor's published price, not ours.---## Tools### 1. `list_vendors`List the vendors VendorBridge reads, and which tools each answers.- **Call:** `GET /vendors`- **Input:** none- **Output:** `[{ "name", "display_name", "capabilities": [...], "notes": {capability: why it is missing} }]`- **Use when:** starting up, or deciding whether a tool is worth calling for a vendor.### 2. `get_vendor`One vendor's capabilities.- **Call:** `GET /vendors/{vendor}`- **Input:**  ```json  {"type": "object", "required": ["vendor"],   "properties": {"vendor": {"type": "string", "enum": ["visions", "pacesetter"]}}}  ```- **Output:** `{ "name", "display_name", "capabilities", "notes" }`. Example: Visions lists no `discounts`, with the note "Visions sells at one price per variant".### 3. `search_products`Browse or search a vendor's catalog. This is the way to find a product's key when you don't have a SKU.- **Call:** `GET /vendors/{vendor}/products?q=&limit=&offset=`- **Input:**  ```json  {"type": "object", "required": ["vendor"],   "properties": {     "vendor": {"type": "string"},     "q": {"type": "string", "description": "every word must appear in the title, handle, SKUs, tags or spec values; part of a word counts; case ignored"},     "limit": {"type": "integer", "minimum": 1, "maximum": 250, "default": 50},     "offset": {"type": "integer", "minimum": 0, "default": 0}}}  ```- **Output:** `{ "vendor", "source", "query", "total", "limit", "offset", "products": [ProductSummary] }`.  - Each `ProductSummary` has `vendor_product` (pass it as `part`), `title`, `url`, `skus`, `variant_count`, `retail_price {min, max, currency}`, `image`, and `sold_blank_only`.- **Ranking:** best match first: an exact SKU, then the query as the whole title, then products with every word in their title. Without `q`, everything sorted by title.- **Paging:** keep raising `offset` by `limit` while `offset < total`.### 4. `get_product`A product's details: title, description, personalization methods, retail price range, attributes.- **Call:** `GET /vendors/{vendor}/products/{part}`- **Input:**  ```json  {"type": "object", "required": ["vendor", "part"],   "properties": {"vendor": {"type": "string"}, "part": {"type": "string"}}}  ```- **Output:**  - The usual `vendor`, `resolution` and `source`.  - `title`, `description_html` and `description_text`.  - `tags`.  - `attributes`: the vendor's own spec table, e.g. `{"Material": "Acrylic", "Production Time": "Minimum 9 Days after art approval"}`.  - `personalization_methods`: `[{handle, source, evidence}]`.  - `retail_price {min, max, currency}`, `variant_count` and `sold_blank_only`.- **`personalization_methods[].source`:**  - `stated`: the vendor's page names the method (PaceSetter's "Imprint Type").  - `inferred`: guessed from the description and tags (Visions). It is weaker; the `evidence` field quotes the text it came from.- **`handle`** uses the same names as the store's `personalization_method` entries: `laser-engraving`, `deep-etch-sandblast`, `etch`, `engraving`, `3d-laser-in-crystal`, `color-fill`, `full-color-print`, `screen-pad-print`, `name-plate`, `back-tag`, `insert`, `hot-stamp`, `photopolymer`, `custom-cast-mold`.### 5. `get_images`The product's photos, each tagged with what it shows.- **Call:** `GET /vendors/{vendor}/products/{part}/images`- **Input:** `vendor`, `part`- **Output:** `images: [{ url, name, role, variant_skus, width, height }]`- **`role`:**  - `variant`: shows the SKUs in `variant_skus`.  - `product`: a general shot (a family shot, a lifestyle photo, a choice sheet).  - `blank`: the piece photographed undecorated, a clean base when the vendor has one.- **The vendor's art templates are never in this list**; use `get_template`.### 6. `get_options`The product's option axes and their values.- **Call:** `GET /vendors/{vendor}/products/{part}/options`- **Input:** `vendor`, `part`- **Output:** `options: [{ name, values }]`, e.g. `[{"name": "Size", "values": ["Small", "Medium", "Large"]}, {"name": "Color", "values": ["Blue", "Red"]}]`. Only axes with more than one value appear.### 7. `get_variants`Every variant, with its image, weight, size and price.- **Call:** `GET /vendors/{vendor}/products/{part}/variants`- **Input:** `vendor`, `part`- **Output:** `variants: [Variant]`. Each `Variant` has:  - `sku`, `label`, and `options` (axis → value).  - `price` (lowest quantity break), `compare_at_price` and `currency`.  - `weight_grams`: null when the vendor doesn't state it.  - `size {label, rank, inches}`.  - `image`: the variant's own photo, else the same piece in the nearest size.  - `blank_image`: the undecorated piece, when the vendor has one.  - `vendor_variant_id`.- **`size`:**  - `label` is the vendor's own wording ("Medium", '4" x 7.875" x 2"').  - `rank` orders sizes (Mini < Small < Medium < Large < XL, or the largest inch number).  - `inches` are the real dimensions, in the order written, only when the vendor states them.### 8. `get_discounts`Quantity pricing: the price per piece at each quantity break, for each SKU.- **Call:** `GET /vendors/{vendor}/products/{part}/discounts`- **Input:** `vendor`, `part`- **Output:**  - `tiers: [{ sku, min_quantity, unit_price, currency, price_code, price_list }]`.  - `notes: [str]`: the vendor's own pricing notes, e.g. "Digi-Color orders less than 6 piece incur a less than minimum charge, $60.00 (V)."- **Reading the tiers:** a tier applies from `min_quantity` up to the next tier's `min_quantity`. The lowest `min_quantity` is the vendor's minimum order (PaceSetter's CM235 starts at 50). `price_code` is the vendor's industry discount code (PaceSetter's "4R").- **501** for a vendor with one price per variant (Visions).### 9. `get_template`The vendor's art template (the drawing that marks the imprint area): whether there is one, and where to download it.- **Call:** `GET /vendors/{vendor}/products/{part}/template?refresh=false`- **Input:**  ```json  {"type": "object", "required": ["vendor", "part"],   "properties": {"vendor": {"type": "string"}, "part": {"type": "string"},                  "refresh": {"type": "boolean", "default": false, "description": "ask the vendor again, ignoring the cached answer. Slow; only when you know the vendor changed the drawing"}}}  ```- **Output:**  - `outcome`: `saved` or `no_template`.  - `sku`, the usual `resolution`, `fetched_at`.  - `download`: the route serving the PDF, e.g. `/vendors/pacesetter/products/4784/template.pdf`; null when there is none.  - `pdf_url`: the vendor's own file link, when it has one.- **Granularity differs by vendor:**  - **Visions:** one drawing per **SKU**. Ask with a SKU; asking with a product key works only when the product has one variant (otherwise 404).  - **PaceSetter:** one PDF per **product page**. A multi-size page's PDF has one page per size, so every SKU of the page returns the same file.- **Speed:** almost always instant (cached). A template VendorBridge has never fetched is downloaded live. For PaceSetter that means a headless browser, about 7 seconds, one at a time. Don't fan out hundreds of uncached template calls at once.### 10. `download_template`The template PDF itself.- **Call:** `GET /vendors/{vendor}/products/{part}/template.pdf`, or simply the `download` path from `get_template`.- **Input:** `vendor`, `part`- **Output:** `application/pdf` bytes. 404 with `"error": "NoTemplate"` when the vendor has none.---## ErrorsVendor errors come back as `{"vendor": "...", "error": "<name>", "detail": "<why>"}`. Auth and validation errors come back as FastAPI's `{"detail": ...}`.| Status | `error` | Meaning | What TrophySync should do ||---|---|---|---|| 401 | (none) | no key, or a key unknown or revoked | check the secret; don't retry || 403 | (none) | the key lacks the route's scope | ask for the scope || 404 | `PartNotFound` | the vendor has no product for that part: not in the crawled catalog (and, for PaceSetter, not found by the vendor's own search either) | treat as not found at this vendor; don't retry before the next weekly refresh || 404 | `UnknownVendor` | no such vendor id | fix the vendor id || 404 | `NoTemplate` | (`template.pdf` only) the vendor has no template | a real answer || 422 | (none) | a bad parameter (e.g. `limit` > 250) | fix the call || 501 | `NotSupported` | the vendor publishes nothing that answers this tool | a real answer; `get_vendor` lists these up front || 502 | `VendorFailed` | the vendor's site answered, but not with what was asked (a page that never loaded, a download that never came) | retry later, with backoff || 503 | `VendorRefusing` | the vendor is throttling us, or the template browser is busy; carries **`Retry-After`** (seconds) | wait `Retry-After`, then retry once || 503 | `CatalogMissing` | the vendor's catalog hasn't been crawled yet | retry later; tell the VendorBridge operator if it persists |Retry policy: honour `Retry-After`. Never retry in a tight loop, because the vendors' sites are small and some throttle for hours when pushed.---## Recipes**Everything about one SKU:**1. `get_product(vendor, sku)`. Check `resolution.matched_by`; treat `prefix` matches as needing review.2. `get_variants(vendor, sku)`, for the variants, prices, weights, sizes and images.3. `get_images(vendor, sku)`, for the full photo set, including `product` and `blank` shots.4. If `discounts` is in the vendor's capabilities: `get_discounts(vendor, sku)`.5. `get_template(vendor, sku)`, then `download_template` when `outcome` is `saved`.All five describe the same vendor product. `resolution.vendor_product` is identical across them, so one product's answers can be stored together under it.**Find a product by name:** `search_products(vendor, q="star tower")`, take `vendor_product` from the result, and pass it as `part`.**Walk a whole vendor's catalog:** page through `search_products(vendor, limit=250)` until `offset >= total`. One call per page, all answered from the cache.**Is the data fresh?** Compare `source.catalog_date` with what you hold. It changes once a week, after the Sunday refresh.---## Vendor notes### `visions`: Visions Awards- **Product key:** the Visions handle (`verge`).- **Sizes are words** (Small/Medium/Large). `size.inches` is filled only when a size label states inches ('8" x 10"').- **Weight:** stated on about half the variants; the rest are null.- **The "Art" choice (Decorated/Blank) is not an option axis.** Each decorated variant's blank twin is its `blank_image` and an image with `role: "blank"`. The exception is a product Visions sells blank only (cornhole bags, bases), which has `sold_blank_only: true` and whose blank rows are its variants.- **Personalization methods are `inferred`, and weak.** Visions states none. Use the `evidence` field.- **No quantity pricing:** `get_discounts` → 501.- **Templates:** per SKU.### `pacesetter`: PaceSetter Awards- **Product key:** the PaceSetter page id (`4784`); the page name (`star-tower-on-marble-base`) works too.- **Sizes are real dimensions** ('4" x 7.875" x 2"', so `size.inches` = `[4, 7.875, 2]`).- **Weight** is per size, converted from the page's pounds.- **Personalization methods are `stated`**, from the page's "Imprint Type". Some pages state none.- **Quantity pricing:** each SKU's price at every break (1/3/6/25, or 50/150 for minimum-quantity items), with PaceSetter's discount code.- **Our part codes often carry a Digi-Color `DC` prefix or a colour suffix.** Both resolve, as `recoded`.- **A part the crawled catalog doesn't know** is looked up once with PaceSetter's own site search. The answer is cached; a miss is retried after 7 days.- **Templates:** per product page. Most are cached; an uncached one takes about 7 seconds in a headless browser.---## Example```bashcurl -s -H "Authorization: Bearer $VENDORBRIDGE_KEY" \  https://vendorbridge.yoordy.com/vendors/pacesetter/products/CD41A/variants``````json{  "vendor": "pacesetter",  "resolution": {"requested": "CD41A", "vendor_product": "4784", "matched_sku": "CD41A", "matched_by": "exact"},  "source": {"url": "https://pacesetterawards.com/product-detail/Star-Tower-on-Marble-Base/4784", "catalog_date": "2026-11-11T..."},  "variants": [    {"sku": "CD41A", "label": "4\" x 7.875\" x 2\"", "options": {"Size": "4\" x 7.875\" x 2\""},     "price": 78.35, "compare_at_price": null, "currency": "USD", "weight_grams": 907,     "size": {"label": "4\" x 7.875\" x 2\"", "rank": 7.875, "inches": [4.0, 7.875, 2.0]},     "image": "https://pacesetterawards.com/Images/ProductImages/Large/CD41_CD41A-_337020.jpg",     "blank_image": null, "vendor_variant_id": "386496"}  ]}```(The response lists CD41B and CD41C too; abridged here.)
